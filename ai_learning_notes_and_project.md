## 1. AI Fundamentals

### Core concepts

- **Context window:** The amount of input and conversation context a model can process for a single request. It is measured in tokens.
- **Tokens:** Units of text processed by a model.
  - **Prompt/input tokens:** Tokens sent to the model.
  - **Completion/output tokens:** Tokens generated by the model.
- **LLM (Large Language Model):** A model trained to understand and generate language.
- **Ollama:** A local LLM server that allows you to run LLMs on your own machine.
- **Embedding model:** A model that converts text or other data into numerical vectors.
- **Vector:** A list of numbers representing data in a form that supports mathematical comparisons.
- **Agent:** An LLM-powered system that can decide which steps or tools to use toward a goal. Unlike a basic LLM call, an agent can choose actions, observe results, and continue. Its autonomy is bounded by the tools and permissions provided.
- **LangChain:** An abstraction framework for composing model calls, prompts, retrievers, tools, and output parsers.
- **LangGraph:** A framework for stateful workflows with nodes, edges, branching, and loops.
- **MCP (Model Context Protocol):** A standardized protocol for AI applications to discover and use capabilities exposed by external servers.

### Chat completion

A chat-completion request usually includes messages with roles, such as `system`, `user`, and `assistant`. The response typically contains the generated message and usage information, including input and output token counts, depending on the provider.

### LangChain concepts

LangChain can reduce coupling to a specific provider and help compose AI pipelines. Common concepts include:

- Model integrations
- Prompt templates
- Retrievers
- Tools
- Output parsers
- Chains and agent workflows

Abstractions help with integration and swapping components, but provider features and API differences can still matter.

## 2. Prompt Engineering

- **Zero-shot prompting:** Give instructions without examples.
- **One-shot prompting:** Give one example showing the expected task or output format.
- **Few-shot prompting:** Give several examples to guide the model.
- **Chain-of-thought prompting:** Encourage multi-step reasoning. This does not guarantee correctness; use deterministic code for calculations or other operations where exact correctness matters.

Example: for a backend API, a prompt template can define the role, constraints, input data, and required response format.

- **Temperature parameter:** Controls the randomness of the generated output. Higher values result in more diverse and creative outputs, while lower values result in more predictable and deterministic outputs.

## 3. Embeddings, Vector Databases, and Semantic Search

### Embeddings

An embedding model converts text into a vector of numbers. Texts with related meanings often have vectors that are close under a suitable similarity or distance measure.

Example:

- `Reset password`
- `Password recovery`

These phrases share meaning even though their keywords differ. Semantic search can retrieve the relevant document even when the wording is different.

### Similarity and scoring

- **Cosine similarity** measures the angle between two vectors; depending on the implementation, higher similarity generally means more alike.
- Other vector stores use distance metrics such as Euclidean/L2 distance, where lower distance generally means closer vectors.
- A score is not automatically a probability or a percentage of correctness. Understand the metric and score direction used by the selected database/model.

### Chunking

Long documents are often split into smaller chunks before embedding.

- **Chunk size:** How much text goes into each chunk.
- **Chunk overlap:** How much text is repeated between adjacent chunks to preserve context around boundaries.

Chunking affects retrieval quality. Very small chunks may lose context; very large chunks may be less precise.

### Vector databases

A vector database stores embeddings and related data, such as the original text and metadata, and supports similarity search. Examples include Chroma and PostgreSQL with pgvector.

Metadata can support filters such as document type, tenant, department, or access level. In a multi-tenant system, authorization must be enforced before returning documents.

## 4. RAG (Retrieval-Augmented Generation)

RAG combines retrieval with LLM generation. It gives the model relevant external content to help ground its answer.

### Typical RAG flow

1. Ingest source documents.
2. Extract and clean text.
3. Split the text into chunks.
4. Generate embeddings for the chunks.
5. Store vectors, text, and metadata.
6. Embed a user's question.
7. Retrieve relevant chunks.
8. Build a prompt containing the retrieved evidence and question.
9. Ask the LLM to answer using that evidence.
10. Return the answer and source references.

```text
Question
   |
   v
Embed question
   |
   v
Vector / hybrid search
   |
   v
Relevant document chunks
   |
   v
Prompt + question
   |
   v
LLM
   |
   v
Answer with sources
```

### Important limitations

RAG does not guarantee correctness. The system can retrieve irrelevant documents, miss the right source, or generate claims unsupported by the evidence.

Useful controls include:

- Relevance thresholds, calibrated to the embedding model and distance metric
- Metadata and permission filters
- Source citations
- A clear abstention response when evidence is insufficient
- Evaluation using representative questions and known relevant documents
- Protection against prompt injection inside retrieved documents

## 5. LangChain and a Simple RAG Pipeline

LangChain can connect an embedding model, vector store/retriever, prompt template, LLM, and output parser.

Conceptually:

```text
Question
  -> Retriever
  -> Retrieved documents
  -> Prompt template
  -> Chat model
  -> Output parser
  -> Answer
```

### Useful implementation details

- Ensure the query embedding model matches the model and vector dimensions used to index documents.
- Handle empty retrieval results before indexing into a result such as `results["documents"][0]`.
- If citations are derived from metadata, verify that expected keys such as `source` exist.
- Use deterministic ordering when presenting source names if stable output is desirable. For example, in Python: `list(dict.fromkeys(sources))`.
- Test the actual retrieval quality. A nearest result is not necessarily a relevant result.
- A temporary Chroma directory is deleted when the temporary-directory context ends; use persistent storage if you need to keep data between runs.

### Example technology choices

- `sentence-transformers` for local embedding models.
- `chromadb` for vector storage and search.
- `langchain` for model/retrieval/prompt abstractions.
- `langchain-community` for integrations that live in the community package.
- `langchain-huggingface` for Hugging Face integrations.
- `numpy` for vector operations and experimentation.

Package names and integration locations can change; check the current documentation for the versions you install.

## 6. LangGraph

LangGraph helps orchestrate stateful workflows. It is useful when an AI task needs branching, repeated steps, shared state, or controlled transitions.

### Core concepts

- **State:** Shared data carried through the workflow.
- **Node:** A function that performs a task and can return updates to state.
- **Edge:** A connection between nodes.
- **Conditional edge:** Chooses the next node based on the current state or routing logic.
- **Compile:** Builds the graph application.
- **Invoke:** Executes the graph.

### Example workflow

```text
User query
    |
    v
 Classify query
    |
    +------ math ------> Calculator tool ----+
    |                                        |
    +------ other ----> Search tool ---------+
                                             |
                                             v
                                            END
```

A state type might be:

```python
from typing import TypedDict

class State(TypedDict):
    query: str
    query_type: str
    result: str
```

Nodes return partial state updates, for example:

```python
{"query_type": "math"}
```

or:

```python
{"result": "Calculation result: 13"}
```

### Practical cautions

- A keyword-based classifier is not an LLM and may misclassify queries.
- An LLM-powered calculator is not equivalent to a deterministic calculator.
- Avoid `eval()` on untrusted input.
- Search tools may return snippets rather than verified facts.
- A hardcoded fallback is simulated search, not real web search.
- Avoid unnecessary complexity: use LangGraph when the workflow genuinely benefits from state, branching, or loops.

## 7. MCP (Model Context Protocol)

MCP standardizes how an AI application connects to capabilities exposed by external servers. Think of it as a common connector interface, rather than a separate AI model.

### Main parts

- **MCP server:** Exposes tools and potentially other capabilities.
- **MCP client:** Connects to servers and discovers/uses their capabilities.
- **Tool:** A callable operation with a name, description, and input schema.
- **Transport:** The communication mechanism, such as `stdio` or a supported network transport.

A server might expose tools such as:

- `search_documents`
- `get_document`
- `get_weather`
- `calculate`

Frameworks such as FastMCP make it easier to create MCP servers. In Python, decorators such as `@mcp.tool()` can expose functions, with arguments described by the function signature and supported schema generation.

### Multiple MCP servers with a LangChain agent

A client can connect to multiple servers, load their tools, and provide them to an agent. The agent's model generally chooses which tool to call; MCP standardizes how the tool is exposed and invoked.

Illustrative configuration based on the lab exercise:

```python
from langchain_mcp_adapters.client import MultiServerMCPClient

client = MultiServerMCPClient({
    "calculator": {
        "command": "python",
        "args": ["/path/to/calculator_server.py"],
        "transport": "stdio",
    },
    "weather": {
        "command": "python",
        "args": ["/path/to/weather_server.py"],
        "transport": "stdio",
    },
})

tools = await client.get_tools()
```

Then create an agent with the model and tools, using the API expected by the installed LangChain version.

### MCP security

Tool availability is not authorization. Validate inputs, authenticate callers, enforce user permissions, restrict sensitive actions, and record important operations. Never treat an LLM's decision to call a tool as proof that the user is authorized.

## 8. How the technologies fit together

| Technology | Responsibility |
|---|---|
| LLM | Understands and generates language |
| Embedding model | Converts data into vectors |
| Vector database | Stores vectors and supports retrieval |
| Semantic search | Retrieves based on meaning |
| RAG | Uses retrieved evidence to help an LLM answer |
| LangChain | Composes models, prompts, retrievers, and tools |
| LangGraph | Orchestrates stateful workflows and branching |
| MCP | Standardizes access to tools and other server capabilities |

These technologies can be combined, but they solve different problems.

## 9. The portfolio project recommendation

### Project name

**Enterprise AI Knowledge Platform**  
Alternative names: `Knowledge Intelligence Platform` or `Enterprise AI Search`.

Replace the existing `Knowledge-Ingestion-Tool-python` pinned project with a more complete, production-oriented AI backend.

### The problem

A company documentation portal receives 10,000 searches daily, with a 60% failure rate. Users search for "Reset password" while the documentation says "Password recovery." Keyword-only search fails because the wording differs.

The project should aim to improve retrieval success, with **95% as a measured target rather than an unsupported claim**.

### Recommended capabilities

1. **Reliable ingestion pipeline**
   - Ingest PDFs, Markdown, HTML, and URLs.
   - Process documents asynchronously.
   - Add retries, idempotency, job status, and incremental re-indexing.

2. **Semantic and hybrid search**
   - Use embeddings for semantic search.
   - Combine vector retrieval with keyword/full-text retrieval.
   - Compare search quality against a keyword-only baseline.

3. **Reranking**
   - Retrieve candidate documents.
   - Use a reranking model to improve result ordering.
   - Measure whether reranking improves ranking metrics.

4. **Grounded answers**
   - Generate answers using retrieved evidence.
   - Include source citations.
   - Abstain when evidence is insufficient.

5. **Evaluation framework**
   - Create representative questions and known relevant documents.
   - Measure retrieval recall, ranking quality, answer correctness, and citation accuracy.
   - Track latency and token costs.

6. **Production controls**
   - Enforce document-level permissions and tenant isolation.
   - Add caching, rate limits, tracing, and usage tracking.
   - Test failures, retries, and concurrent requests.

7. **LangGraph workflows**
   - Add a workflow only when it provides useful control, such as deciding whether evidence is sufficient, searching again, asking a clarifying question, or abstaining.

8. **MCP integration**
   - Expose capabilities such as `search_documents` and `get_document`.
   - Let an external AI client discover and invoke them.
   - Keep authorization and validation in the backend.

### Suggested stack

| Component | Technology |
|---|---|
| API | Python + FastAPI |
| Database | PostgreSQL |
| Vector search | Chroma initially, or PostgreSQL + pgvector |
| Background processing | Redis + Celery |
| Embeddings and reranking | Sentence Transformers |
| AI integrations | LangChain |
| Stateful workflows | LangGraph, when justified |
| Tool interoperability | MCP |
| File storage | MinIO or S3-compatible storage |
| Observability | OpenTelemetry |
| Deployment | Docker Compose and CI/CD |

You do not need every component in the first version. Build incrementally and justify each addition.

## 10. Can Chroma be used without installing it locally?

Yes. There are three main options:

| Option | How it works | Best for |
|---|---|---|
| Chroma Cloud | A managed, hosted vector database accessed over the network | Avoiding local database setup |
| Chroma in Docker | Run Chroma as a containerized service | Learning deployment and self-hosting |
| Embedded Chroma | Install the Python package and store data locally without a separate database server | Learning the basics quickly |

If you want to avoid running a database locally, start with Chroma Cloud. If you later want to learn self-hosting, move to Docker.

Official documentation: [Chroma documentation](https://docs.trychroma.com/).

A hosted vector database does not necessarily mean your embedding model is hosted. You can still generate embeddings locally with Sentence Transformers or use a hosted embedding API.

## 11. A staged learning roadmap

### Phase 1 — Embeddings and semantic search

Start with a small collection of company documents, such as:

- Password recovery
- Remote work policy
- Annual leave policy
- Office security policy

Use Sentence Transformers to embed each document and query. Inspect the vectors and compare search results.

Test questions such as:

- `Reset password`
- `Work from home`
- `How many vacation days do employees receive?`

Learn why each result was retrieved before introducing additional frameworks.

### Phase 2 — Add Chroma

Store document chunks, embeddings, and metadata in Chroma. Learn similarity search, metadata filtering, persistence, and the difference between similarity and distance scores.

### Phase 3 — Add RAG and LangChain

Connect retrieval, prompt templates, and an LLM. First understand the retrieval and prompting steps directly; then use LangChain to understand what the abstraction provides.

### Phase 4 — Add LangGraph

Introduce conditional workflows when the system needs to make decisions or repeat steps.

### Phase 5 — Add MCP

Expose search functionality as an MCP server so compatible AI clients can discover and use it.

### Phase 6 — Make it portfolio-worthy

Add evaluation, permissions, reliable background processing, observability, deployment, and a clear README documenting measured results.

## 12. What to do first

Start with this small implementation:

1. Create 10–20 sample company documents.
2. Embed them using Sentence Transformers.
3. Search for "Reset password" and retrieve "Password recovery."
4. Search for "Work from home" and retrieve "Remote work policy."
5. Store the documents in Chroma.
6. Measure search quality against a keyword-search baseline.

Do not begin with LangGraph or MCP. You will understand their value more clearly after you have a working search engine.

### The learning rule

For every code component, answer three questions:

1. **What goes in?**
2. **What happens internally?**
3. **What comes out?**

For example, `model.encode(query)` converts text into a numerical vector. Once you understand the vector and how it is compared with document vectors, a vector database becomes much easier to understand.

**The goal:** Build one substantial project while learning the fundamentals, instead of collecting disconnected tutorial examples.
